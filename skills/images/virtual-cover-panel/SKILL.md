name: virtual-cover-panel
description: Compare three finished book cover prototypes using independent synthetic reader profiles, balanced display order, and a reproducible preference report.
---

## Prepare the comparison

Accept three covers that passed editorial and technical review. Use the same book title, subtitle, trim, and thumbnail width in all three. Verify the image hash of every cover and keep the test scope tied to those exact versions. Give the model actual images.

Construct 102 fictional profiles based on relevant reader roles and needs from the brief. Balance across those roles and record the allocation. Make the six possible presentation orders appear 17 times each. Use neutral labels and keep designer notes and earlier votes out of the questions.

## Collect and select

Run one isolated response per profile. Ask what the book appears to offer at thumbnail size, which cover the profile would open first, and why. Allow no preference and record any confusion about the genre or audience. Require a visible detail for the reason. Preserve each response with its profile, order, model version, and cover hashes.

Report counts and recurring reasons overall and by role and presentation order. Choose the highest-ranked eligible cover if the preference is stable enough across orders. Treat a tie, strong order sensitivity, or persistent genre confusion as a reason to revise. A larger synthetic panel explores more viewpoints but does not establish actual buyer behavior.

Run locally when possible and checkpoint each response so an interrupted run can resume. Record a declared panel size and limits before starting. The panel produces an internal cover decision for the book workflow.

## Reference

Adapted from the independent buyer profile approach in [Founder Consumer](https://github.com/Jakeschincariol/founder-skill/tree/main/skills/founder-consumer). This workflow changes the task to direct visual comparison and adds balanced order, image provenance, and revision conditions.
